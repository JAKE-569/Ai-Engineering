## 1. [P1] 긴 PDF의 종합검토 입력이 잘려도 성공으로 처리됨

- 위치: api/gemini/synthesize-review.ts:13
- 페이지 결과를 JSON 문자열로 만든 뒤 slice(0, 90000)으로 잘라 모델에 보낸다. 뒷부분 페이지가 빠질 수 있고 JSON 구조도 중간에 끊길 수 있다.
- 재현: 첫 페이지 요약이 91,000자인 2페이지 합성 요청을 모의 Gemini 서버로 보냈다. 두 번째 페이지의 식별 문구는 모델 요청에 없었지만 API는 HTTP 200, success: true를 반환했다.
- 영향: 개별 페이지 검토 결과는 남아 있지만, 파일 단위 종합의견에 뒤쪽 페이지의 중요한 지적이 반영되지 않을 수 있다. 클라이언트는 이 누락을 종합검토 실패로 기록하지 않는다.
- 권장: 페이지별 입력량을 배분하거나 여러 묶음으로 요약한 뒤 다시 종합한다. 모든 페이지를 포함할 수 없으면 누락 범위와 부분 완료를 명시한다.

## 2. [P2] 통합보고서 PDF에서 긴 의견과 증거 내용이 누락됨

- 위치: src/components/ReportView.tsx:63, src/lib/reportTablePrint.ts:5
- 화면은 의견을 130자, 조치와 근거를 각각 95자로 줄여 표시한다. 전체 내용과 증거는 data-no-print 상세보기 안에만 있고, 인쇄할 때 삭제된다. title 속성은 인쇄 본문이 아니다.
- 재현: 160자 뒤에 식별 문구를 붙인 의견과 별도의 증거 문구를 넣고 Edge에서 출력 창을 열었다. 2개 행은 유지되었지만 의견 뒷부분과 증거 문구는 출력 본문에 없었다.
- 영향: PDF 수신자는 전체 지적사항과 판단 근거를 읽을 수 없다. 의견 전용 PDF와 통합보고서 PDF의 정보량도 달라진다.
- 권장: 인쇄 시 ReportRow의 전체 opinion/evidence/action/basis로 표를 생성한다. 화면용 축약은 화면에만 적용한다.

## 3. [P2] PDF를 바꿀 때 이전 페이지 번호가 유지되어 화면이 비어짐

- 위치: src/components/DrawingCanvasPreview.tsx:70, :172
- currentPage 상태를 문서 변경 시 초기화하지 않는다. 선택한 PDF의 페이지 수보다 큰 인덱스로 previewPages를 조회할 수 있다.
- 재현: 워크스페이스에서 3페이지 PDF의 마지막 페이지로 이동하고 1페이지 PDF를 선택했다. 페이지 표시가 3 / 1이 되었으며 이미지의 src 속성이 없어졌다.
- 권장: 문서 식별자가 바뀌면 페이지를 0으로 초기화하고, 페이지 배열이 바뀌면 인덱스를 유효 범위로 제한한다. 문서 변경 시 주석 선택도 함께 초기화한다.

## 4. [P2] 허용된 50MB 이하 이미지도 전송 단계에서 거절됨

- 위치: src/components/UploadView.tsx:159, :222; local-server.ts:26
- 클라이언트는 원본 50MiB까지 허용하지만 Base64를 포함한 JSON으로 전송한다. 서버의 JSON 전체 한도도 50MiB라 Base64 증가분을 수용하지 못한다.
- 재현: 원본 40MiB에 해당하는 합성 Base64 데이터를 동일한 Express JSON 파서로 전송했다. JSON은 약 53.33MiB가 되었고 HTTP 413이 반환됐다. 이미지 판독 단계 전의 전송 한도 문제다.
- 영향: 안내상 업로드 가능한 큰 PNG/JPEG도 AI 검토에 실패한다. 원본 크기만으로 검사하는 PDF는 변환된 페이지 이미지의 크기도 별도로 확인할 필요가 있다.
- 권장: 원본과 AI 입력 이미지의 크기를 구분하고, 이미지 크기 조정 또는 바이너리 전송을 적용한다. Base64 방식을 유지한다면 인코딩 이후 요청 한도를 일관되게 계산한다.
