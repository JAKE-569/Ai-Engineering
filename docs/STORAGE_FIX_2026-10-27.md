# 로컬 삭제 EPERM 수정 — 2026-10-27

## 재현과 원인

사용자가 도면 업로드 화면에서 '로컬 저장 실패 (500)'와 EPERM을 보고했다. 실제 저장 결과 목록 읽기는 HTTP 200으로 정상이고, 사용자 계정의 저장 폴더 접근 권한도 FullControl이었다.

실행 중인 개발 서버에서 임시 문서를 만들고 2.5초 뒤 삭제하자 동일한 EPERM 500을 재현했다. 삭제는 문서 폴더를 먼저 이름 변경한 후 제거하는데, Windows에서 Vite의 디렉터리 감시 핸들이 이름 변경을 방해했다. local-data를 Vite 감시에서 제외하자 같은 시험이 HTTP 204로 성공했다.

## 변경

- vite.config.ts: local-data 및 하위 경로를 코드 변경 감시에서 제외.
- local-review-store.ts: 파일/폴더 이름 변경의 일시적인 EPERM/EBUSY/EACCES에 제한된 재시도 적용. 임시 파일 정리 실패가 원래 저장 오류를 덮지 않도록 처리.
- 잠금이 계속되면 HTTP 423과 한국어 안내, 실패 작업 종류를 반환. 서버에는 메서드·경로·오류 코드·시스템 호출을 기록하며 도면 내용은 기록하지 않음.
- localReviewClient.ts: 읽기·저장·삭제 실패를 구분. 기존 서버의 EPERM JSON 응답도 읽기 쉬운 안내로 변환.
- 실행 중인 로컬 서버를 새 코드로 재시작.

## 검증

- TypeScript 검사와 Vite 빌드 통과.
- 단위/API 테스트 11개, Edge 브라우저 시나리오 2개 통과.
- 일시적인 이름 변경 잠금 후 재시도 성공, 지속 잠금 시 삭제 실패와 기존 레코드 보존, 클라이언트 삭제 오류 안내를 자동 테스트.
- 실제 실행 서버에서 임시 데이터 생성·저장·수정·삭제 확인.
- 기존 검토 결과 1건은 삭제하거나 변경하지 않음. review.json의 SHA-256을 수정 전후 비교해 동일함을 확인.

## 사용 안내

프로그램 시작 시 이전 검토 결과가 나타나는 것은 local-data 자동 복원 기능의 정상 동작이다. 빈 화면으로 시작하도록 바꾸거나 기존 기록을 초기화하는 변경은 하지 않았다.

브라우저에서 Ctrl+F5로 새로고침하면 이전 화면에 남은 오류 메시지가 정상 읽기 결과로 갱신된다.
